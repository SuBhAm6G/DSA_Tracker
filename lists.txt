# MODULE 21 — PROBLEM-SOLVING METHOD

For every significant problem, practice:

## Step 1 — Understand

* Inputs
* Outputs
* Constraints
* Edge cases

## Step 2 — Brute force

* Direct solution
* Complexity

## Step 3 — Identify bottleneck

* Repeated computation
* Repeated search
* Repeated range calculation
* Unnecessary sorting
* Nested loops

## Step 4 — Choose technique

Potential choices:

* Hashmap
* Set
* Sorting
* Two pointers
* Sliding window
* Prefix sum
* Binary search
* Heap
* Stack
* Greedy
* DP

## Step 5 — Optimize

Compare:

* Time
* Space
* Simplicity

## Step 6 — Implement in Python

Focus on:

* Clean code
* Correct use of built-ins
* Readability
* Avoiding unnecessary complexity

## Step 7 — Test edge cases

* Empty input
* One element
* Duplicates
* All equal
* Negative numbers
* Zero
* Already sorted
* Reverse sorted
* Very large values
* Boundary conditions

# MODULE 24 — PRODUCT-COMPANY OA STRATEGY

## 24.1 Hidden-pattern identification

The question should **not tell you the algorithm**.

Learn to infer:

* "Nearest future greater" → monotonic stack
* "Dependencies" → graph/topological sort
* "Repeated range query + updates" → segment tree/Fenwick
* "Prefix matching" → Trie/KMP
* "Dynamic connectivity" → DSU
* "Many states across positions" → DP
* "All possible valid configurations" → backtracking
* "All-pairs path" → Floyd-Warshall
* "Negative edge" → Bellman-Ford
* "Many interval events" → line sweep

## 24.2 Multiple valid solutions

Learn to compare:

* O(N²)
* O(N log N)
* O(N)
* O(log N)
* O(1) auxiliary space

and justify why a higher-quality product-company solution is preferable.

## 24.3 Constraint-driven algorithm selection

Given constraints such as:

* N ≤ 20
* N ≤ 10³
* N ≤ 10⁵
* N ≤ 10⁶

infer the expected algorithmic complexity.
